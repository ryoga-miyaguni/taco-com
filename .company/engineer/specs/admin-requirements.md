# 管理画面 要件定義

## ビジョン

**プログラミングに関心がない人でも、このシステムを単独で管理運営できる UI** を目指す。
技術的知識を前提としない、ノーコード管理者向けダッシュボード。

## 必須機能（v1 で全て実装する）

### 1. 店舗の追加（運営による直接登録）
- フォームから店舗情報を入力して即時登録
- 入力項目: 店名、住所、緯度経度（住所からジオコーディング推奨）、種類、営業時間、特徴メモ
- 地図上でピンをドラッグして位置調整できると理想

### 2. 店舗追加申請の承認/却下
- ユーザーから送られた申請を一覧表示
- 「承認」で公開、「却下」で削除（理由メモ可）
- 承認時は本登録の店舗テーブルへ自動コピー

### 3. 通報の管理
- 通報が来たコメント・店舗を一覧表示
- 通報理由・通報者数・対象内容を確認可能
- アクション: 「問題なし（通報を却下）」「コメント削除」「店舗非表示」
- 通報3件で自動 is_hidden（要件 v1.2 既定）→ 管理者が最終判断

### 4. 不適切コメントの削除
- 全コメントの一覧（店舗別フィルタ可）
- 個別削除、複数選択一括削除
- 削除理由をログに残す

### 5. 不適切ユーザー（ゲスト）のBAN
- guest_id 単位でブロック
- BAN したゲストの過去コメントを一括非表示にするオプション
- IP単位のBANも検討（プラポリ要記載）

### 6. 店舗一覧の管理・編集
- 全店舗を表で表示
- 絞り込み: 種類、エリア、登録日、表示状態（公開/非表示）
- 検索: 店名、住所での部分一致
- 行クリックで編集モーダル → 全フィールド修正可
- 削除（論理削除）

### 7. アナリティクス
- 日別アクセス数、ユニークビジター
- 人気店舗ランキング（詳細パネルを開いた回数）
- コメント投稿数推移
- エリア別ヒートマップ
- 検索キーワード上位

## UI/UX 原則

- **専門用語を避ける**: 「Row」「Record」「Schema」などの DB 用語を出さない
- **確認ダイアログ必須**: 削除・BAN・承認は必ず確認画面を経由
- **アクション結果の即時フィードバック**: トースト通知で成功/失敗を明示
- **一画面一目的**: ダッシュボードからカード式で各機能へ遷移
- **モバイル対応**: スマホからも管理操作できる

## 技術的考慮事項

- 認証: Supabase Auth（メール+パスワード）。管理者のみ `/admin` にアクセス可
- 認可: Supabase RLS で admin ロールチェック
- 監査ログ: 誰がいつ何をしたかを `admin_actions` テーブルに記録
- アナリティクス: 自前の `page_views` テーブル + 集計クエリ（または Plausible/Umami 検討）

## 実装フェーズ

このページは **Supabase 接続後** に本格実装する。
現状（LocalStorage のみ）では:
- 店舗追加・編集は demo-shops.json の手動更新が必要
- 申請・通報・BAN・アナリティクスはバックエンドが必要なため未実装
- 暫定で「店舗統計の閲覧のみ」を提供している

## 開発優先順位（Supabase接続後）

1. 認証 + 管理者ロール
2. 店舗一覧管理（編集・削除）
3. 店舗追加（直接登録）
4. 申請承認フロー
5. 通報管理 + コメント削除
6. ゲストBAN
7. アナリティクス
