## 1. プロジェクト概要
- **目的:** 沖縄県内のタコス店を地図上で視覚的に探しやすくし、ユーザー同士のリアルな口コミ（熱量）を共有できるコミュニティプラットフォームを構築する。
- **ターゲットユーザー:** 沖縄県民、観光客、タコス愛好家。
- **コアバリュー:** ログイン不要の圧倒的な手軽さと、Mapboxを活用した直感的でリッチな地図体験。

## 2. システム構成案（技術スタック）
初期費用を最小化（月額ほぼ無料）しつつ、スケーラビリティを確保するモダンな構成とする。

- **フロントエンド:** Next.js (React), Tailwind CSS
- **地図エンジン:** MapLibre GL JS + react-map-gl（OSS・ライセンス料なし）
- **地図タイル:** Protomaps（沖縄県エリアに限定した `.pmtiles` を Cloudflare R2 に配置）
  - 転送料無料の R2 経由配信で月額ほぼゼロ
  - バズっても料金青天井にならない
- **バックエンド / データベース:** Supabase (PostgreSQL / PostGIS で位置情報検索を高速化)
- **店舗データ取得方針:** 外部API不採用。**運営承認制の申請フォーム**で追加する
- **ホスティング:** Vercel

## 3. 機能要件

### 3-1. ユーザー向け機能（ログイン不要）

| 機能名 | 詳細・仕様 |
| :--- | :--- |
| **マップ表示機能** | ・Mapboxを用いた全画面マップ表示<br>・タコス専用のカスタムピン表示<br>・店舗密集エリアのクラスタリング（グループ化）表示 |
| **店舗検索・絞り込み** | ・エリア検索（那覇、中部など）<br>・特徴フィルター（ハードシェル、ソフトシェル、タコライス等） |
| **現在地連携** | ・ユーザーの現在地を取得し、マップの中心を移動<br>・現在地から近い順の店舗リスト表示（Supabase PostGIS活用） |
| **店舗詳細表示** | ・ピンをタップでポップアップ、または画面下部から詳細パネルを引き上げ表示<br>・店舗名、住所、営業時間、平均評価、写真を表示 |
| **コメント（口コミ）投稿** | ・**ゲスト状態（匿名）での投稿**<br>・`guest_session_id` (UUID) を LocalStorage に発行<br>・テキストコメント＋星評価（1〜5）の投稿<br>・自分が過去に投稿したコメントの編集・削除を許可（guest_session_id 一致で判定） |
| **リアクション機能** | ・他人のコメントに対する「いいね」ボタン（ゲストOK） |
| **通報機能** | ・不適切なコメントの通報ボタン<br>・同一 guest_session_id からの通報は1件扱い（水増し防止）<br>・**通報3件到達で自動 `is_hidden = true`**（運営レビュー待ち状態） |
| ~~**店舗追加申請**~~ | **v1.5 以降に延期**。v1 では運営が管理画面から手動追加のみ |

### 3-2. 管理者（運営）向け機能

**アーキテクチャ:** 同一アプリ内の `/admin` ルートとして実装。Next.js Route Groups (`(public)` / `(admin)`) で分離し、`middleware.ts` + Supabase Auth + RLS で保護する。管理者は `user_metadata.role = 'admin'` で識別。別アプリ化はしない。

| 機能名 | 詳細・仕様 |
| :--- | :--- |
| **管理者ログイン** | ・Supabase Auth（Email + Password またはマジックリンク）<br>・`/admin/login` |
| **店舗データ管理** | ・新規タコス店の登録・編集・削除<br>・緯度経度の地図ピック入力<br>・写真アップロード（Supabase Storage） |
| **コメントモデレーション** | ・全コメント一覧（通報多い順・新着順）<br>・通報閾値到達 (`is_hidden = true`) コメントのレビュー・復帰・削除<br>・guest_session_id / IP アドレスのブロック |
| **申請レビュー（v1.5〜）** | ・`pending_shops` の審査・承認・却下 |

### 3-3. v1.5以降の予定機能：ユーザー登録（段階的オプトイン）

v1 はログイン不要で出すが、将来的な登録導線を前提に設計する。

**登録ユーザーのメリット（インセンティブ設計）:**
- 端末を跨いで投稿履歴・お気に入りが保持される
- お気に入り店舗の保存、マイリスト、「行ったお店マップ」
- お気に入り店舗の新着コメント通知
- プロフィール・バッジ（食破数など）
- 登録者の口コミは信頼バッジ付きで表示
- 登録者の通報は重み付け 1.5倍

**運営側のメリット:**
- モデレーションコスト激減（アカBANが効く）
- 登録者にはレート制限を緩められる
- 将来のマネタイズ（広告・店舗プラン）の前提
- コミュニティ形成・リピーター可視化

**重要な設計:** ゲスト投稿を後からアカウントに紐付けられる仕組み（`guest_session_id` → `user_id` マージ）を v1 の段階から DB スキーマに織り込んでおく。

## 4. 非機能要件
- **スパム・荒らし対策（重要）:**
  - Cloudflare Turnstile（またはreCAPTCHA v3）を導入し、Botによるコメント投稿を弾く。
  - 同一IPアドレスからの連続投稿制限（例：1時間に5回まで）。
  - 通報自動非表示ルール（上記 3-1）。
- **法務（必須）:**
  - プライバシーポリシーを公開必須（`ip_address` 保存のため個人情報扱い）。
  - 利用規約（投稿コンテンツの扱い・禁止事項・モデレーション方針）を公開必須。
  - MVPリリース前に公開する。
- **パフォーマンス:**
  - 地図の初期ローディングを3秒以内に完了させる。
  - 店舗データは初回ロード時に軽量なJSONとして取得し、詳細データはタップ時に非同期通信する。
- **レスポンシブ対応:**
  - モバイルファースト（スマホでの親指操作を前提としたUI/UX）。PCブラウザでも崩れずに閲覧可能にする。
- **運用コスト:**
  - リリース初期は、インフラ・APIコストを月額1,000円未満に抑える構成を維持する。

## 5. データベース設計（主要テーブル案・Supabase）

### 5-1. `shops` テーブル（承認済み店舗）
- `id`, `name`, `latitude`, `longitude`, `address`, `type`, `business_hours`, `photo_url`, `created_at`, `updated_at`

### 5-2. `pending_shops` テーブル（ユーザー申請・未承認）
- `id`, `name`, `latitude`, `longitude`, `address`, `type`, `note`, `submitted_by_guest_id`, `submitted_by_user_id` (nullable), `status` (pending/approved/rejected), `created_at`

### 5-3. `comments` テーブル（口コミ）
- `id`, `shop_id`, `guest_session_id`, `user_id` (nullable, v1.5〜), `body`, `rating`, `ip_address`, `is_hidden`, `report_count`, `created_at`

### 5-4. `reactions` テーブル（いいね）
- `id`, `comment_id`, `guest_session_id`, `user_id` (nullable), `created_at`
- UNIQUE (comment_id, guest_session_id) で重複防止

### 5-5. `reports` テーブル（通報）
- `id`, `comment_id`, `reporter_guest_id`, `reporter_user_id` (nullable), `reason`, `created_at`
- UNIQUE (comment_id, reporter_guest_id) で水増し防止
- INSERT時トリガーで `comments.report_count` を更新し、3件到達で `is_hidden = true`

### 5-6. `users` テーブル（v1.5〜）
- Supabase Auth の標準 users に紐付け。プロフィール拡張用
- `id`, `display_name`, `avatar_url`, `linked_guest_ids` (過去のゲストIDマージ用)

## 6. v1 スコープ（最小構成）

**実装する:**
- 地図表示（MapLibre + Protomaps）
- 承認済み店舗のピン表示・クラスタリング・詳細パネル
- ゲスト口コミ投稿・編集・削除（LocalStorage + guest_session_id）
- いいね・通報
- 自動非表示（通報3件）
- `/admin` ルート（店舗CRUD + モデレーション）

**v1.5 以降に延期:**
- ユーザー登録（段階的オプトイン）
- 店舗追加申請フォーム（`pending_shops`）
- お気に入り・マイリスト・通知
- バッジ・称号
